top of **[RustDesk](https://github.com/rustdesk/rustdesk)**.

## What is in this repository

| Path | What it is |
|---|---|
| `src/`, `libs/`, `res/` | The RustDesk core (Rust), with the modifications listed below |
| `src/merlin.rs`, `src/merlin_bridge.rs` | **merlin-bridge**: a headless RustDesk session (viewer, file transfer, or host) driven over stdin/stdout. Merlin ships this binary next to its own executable and talks to it as a separate process |
| `src/merlin_client.rs` | API used by the client UI (ID, passwords, connection manager, service install) |
| `client/` | **Merlin-RustDesk client** for end customers: a Tauri 2 + React UI on top of the RustDesk core (Windows, Linux, macOS) |
| `scripts/` | Helper scripts to publish client builds |

Merlin itself (the technician application) is a separate program and is **not**
part of this repository; it only runs `merlin-bridge` as an external process.

## Modifications (imeandrea, October 2026)

Starting from RustDesk `master` (version 1.5.1), this version:

- removes the parts not used here: the Flutter UI, mobile apps (fastlane),
  packaging, docs and CI workflows;
- adds `merlin-bridge` (feature `merlin`): controlling session driven by
  Merlin, screen frames as changed tiles, input, clipboard, multi-monitor,
  chat, remote restart with automatic reconnection, file transfer
  (browse, upload, download, mkdir, rename, delete), automatic choice of the
  Windows session, and a *host* mode so Merlin itself can receive support;
- adds `merlin_client` and the `client/` application: main window with ID and
  password, incoming requests in a bottom panel, chat, tray icon, unattended
  access (permanent password, "start with the computer" as a Windows service or
  a systemd service on Linux), customisation (name, logo, colour, contacts,
  server) appended to the executable, and an *About and licences* window;
- makes the API server (`api-server`) configurable from Merlin or from the
  customisation.

The complete list of changes is the git history of this repository on top of
the upstream commit (`git log` after the RustDesk history). Each new file is
marked with its origin; modified upstream files keep their original headers.

## Building

Requirements: Rust (stable), [vcpkg](https://github.com/microsoft/vcpkg) with the
RustDesk dependencies (`libvpx`, `libyuv`, `opus`, `aom`; baseline in
`vcpkg.json`), and on Windows LLVM (`LIBCLANG_PATH`). Node.js 22+ for the client UI.

```bash
git submodule update --init --recursive

# merlin-bridge (used by Merlin)
VCPKG_ROOT=/path/to/vcpkg cargo build --release --features merlin --bin merlin-bridge

# client for customers
cd client
npm ci
VCPKG_ROOT=/path/to/vcpkg npx tauri build
```

The published client has **no default server**: on first start it asks for the
server ID, key, relay and API server, and they can be changed later. A client
customised by Merlin carries its server inside the file and cannot be changed.
A private build can compile a fixed server from `client/.env`
(`MERLIN_RD_SERVER`, `MERLIN_RD_KEY`, `MERLIN_RD_RELAY`, `MERLIN_RD_API`,
`MERLIN_RD_TYPE`); that file is not part of the repository and must not exist
when building public releases. Linux builds need the usual RustDesk
packages plus `libayatana-appindicator3-dev` and `libxdo-dev`.
